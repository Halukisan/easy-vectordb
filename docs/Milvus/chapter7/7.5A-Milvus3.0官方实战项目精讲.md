| # | Demo | 核心特性 | 介绍 | 数据 |

**环境要求**：复用第 7 章的 lab（Milvus v3.0.2 @ 127.0.0.1:19530，docker compose 已起）。Demo 2/3/4/5 需要一个 OpenAI 兼容的**嵌入 API**（示例用阿里云百炼 `text-embedding-v4`，1024 维），在环境变量里准备：

```bash
export EMB_KEY=你的嵌入API密钥        # Windows: set EMB_KEY=...
# 可选：export EMB_EP=...  EMB_MODEL=...   换别的提供商
```

官方 demo 用本地模型（BGE-M3 ONNX / ColSmol 视觉模型）烘在镜像里；教学版换成 API 嵌入，**Milvus 侧的 schema、函数、索引、搜索协议完全不变**——这正是想教的东西。

**两条通用纪律**（每个 notebook 都会踩）：

1. `insert` 之后必须 `client.flush(collection)` 再 `load + search`——跳过 flush 的"查不到结果"占了新手问题的一大半；
2. 嵌入向量**必须同源**：文档和查询用同一个模型、同一个维度，混用必然全错。


## 7.5A.1 Demo 1 · MinHash 近重复检测（零模型，最容易跑）

**它解决什么**：判断"这篇文档是不是那篇的抄袭/变体"。传统向量检索靠语义，但"复制粘贴改几个词"的文档语义几乎不变、向量几乎相同——反而抓不出**字面级**的重复。MinHash 反过来：不看语义，只看字面 shingle 的重合率（Jaccard 相似度），而且**全程在 Milvus 内部完成**，不需要任何嵌入模型。

**notebook**：`7.5A-01-MinHash近重复检测.ipynb`。链路：36 篇短文（7 个主题簇 × 原文/复制/轻编辑/增删段落/同题无关 等变体）→ 建集合时挂一个 `MINHASH` 函数（`num_hashes=256, shingle_size=1`），插入纯文本、签名由服务端自动算 → `MINHASH_LSH` 索引 → 搜索直接给估计 Jaccard。

**实测数字**（跑出来应看到）：

| 变体 | 与原文的 distance |
|------|------------------|
| 原文自己 / 完全复制 | 1.0000 |
| 轻编辑（改词、换序） | 0.72 ~ 0.96 |
| 增/删一个段落 | 0.72 ~ 0.79 |
| 同主题不同文 / 无关文 | < 0.13 |

阈值 0.5 一刀切干净：**变体全在上方，无关全在下方**，36 篇的 top1 中位数 0.90。

**坑**：`MHJACCARD` 的 distance **直接就是 Jaccard 相似度**（越大越像，1.0=逐字相同），别再拿它当"距离"去做 `1 - d`；`shingle_size=1`（按词）是官方实测调过的——调到 3，两词之差的轻编辑相似度会从 0.85 掉到 0.70，开始误判。

## 7.5A.2 Demo 2 · 函数链重排：向量管"像不像"，业务管"该不该排前"

**它解决什么**：纯向量排序只懂语义相似，不懂生意——好评多的、近期上架的、价格贴着心理价位的，理应更靠前。3.0 的 **L0 Function Chain** 把"特征计算 + 模型打分"搬进数据库：召回后服务端自动跑一条链，输出业务分。

**notebook**：`7.5A-02-函数链重排.ipynb`。链路（全部可复现）：

1. 官方 240 商品（含预计算 1024 维向量）+ 1440 条训练记录；
2. **训练 XGBoost**：5 特征（语义分/评分/流行度/价格亲和/新鲜度），`monotone_constraints=(1,1,1,1,1)` 单调约束保证"分越高排越前"学不歪。产出的 UBJ 模型文件 **115,265 字节，与官方逐字节一致**（数据与超参全冻结：depth2 / eta0.08 / 128 轮 / seed42）；
3. 模型经 MinIO 上传后 `add_file_resource` 注册——Milvus 从自己的对象存储读模型，**推理发生在数据库进程里**；
4. 建链：`num_combine`(流行度) → `decay`(价格/新鲜度) → `round_decimal`(语义分) → `xgboost`，然后同一条查询跑两遍：普通向量序 vs `function_chains=chain` 业务序。

**实测数字**：6 条查询的双榜对比里，top-10 集合重合 10/10，但**名次普遍位移 6~14 位**（例如耳机查询 top1 从第 28 名提到第 25 名）——语义盘由向量定，业务盘由模型微调，两者分工清楚。官方报告重排后 NDCG 0.9976。

**坑**：链输出进 `$score` 后，**语义已不是余弦值而是 0~1 的业务分**，阈值、排序、展示都按新量纲来；`FileResource` 是**集合之外的资源**，删集合不会删资源，要显式 `remove_file_resource`。

## 7.5A.3 Demo 3 · StructArray：一行装下"视频 + 它的 18 个目标"

**它解决什么**：行车记录仪一帧里有多个目标（卡车/行人/自行车），每个目标都有自己的描述和向量。老做法是拆两张表（视频表 + 目标表）再 join；3.0 的 **`ARRAY<STRUCT>`** 把 18 个子记录（各带自己的向量）直接嵌在视频行里，一次查询能分别问"哪段视频整体最像"和"哪个具体目标最像"。

**notebook**：`7.5A-03-StructArray父子混合检索.ipynb`。30 段合成驾驶场景 × 6 目标 × 3 时相 = 540 条子观察，文本用嵌入 API 向量化。三种问法：

- **A 父向量**：对 `summary_vector` 普通检索——"哪段视频整体像"；
- **B 子向量 + 归并**：对 `observations[description_vector]` 检索并传 `group_by_field="video_id"`——按目标命中，但**每段视频只回一条**（组内最优）；
- **C 加权融合**：`hybrid_search` 同时发 A/B 两个请求，`WeightedRanker(0.4, 0.6)` 融合，子请求带 `element_scope.collapse {strategy: topk_sum, topk: 3}` 把一行的多个子命中折成一行一分。

**实测数字**（"路口的白色卡车"类查询）：A 路 top1 与 C 路 top1 不同——C 路靠子目标证据把 005 号视频顶到第一，这正是父子融合的价值。

**坑**：B 路的按组归并用 **`group_by_field`**（search 的顶层参数）；C 路 hybrid 里的元素级折叠用 **`element_scope.collapse`**（放在该路 `param.params` 里）——两个机制长得很像但入口不同；`max_capacity` 必须声明，结构数组超容量会截断。


## 7.5A.4 Demo 4 · EmbeddingList：把"哪一页讲了这件事"问准

**它解决什么**：一份 356 页的手册，问"利益相关方期望怎么变成技术需求？"——整页压成一个向量会"平均掉"页内细节，答案页和相邻页分不开。做法：**每页切成多个 patch，各自嵌入**，一页 = 一组向量。查询时对每个候选页算"query 与页内所有 patch 的最大相似度"（MAX_SIM），谁页里有最贴的段落谁排前。

**notebook**：`7.5A-04-EmbeddingList多向量检索.ipynb`。官方用 ColSmol 视觉模型给**页面截图**打 patch 向量；教学版用 pypdf 提取 40 页文本、按句子聚合 ~700 字符一块、嵌入 API 打 1024 维向量——检索机制一模一样。schema 上 patch 放在 `patches ARRAY<STRUCT>` 里，索引建在 `patches[patch_embedding]`、metric 是 **`MAX_SIM_COSINE`**；查询向量用 `EmbeddingList` 包装。

**实测数字**：官方 8 条真实问题（每条带标准答案页 + 一个"相近但不是答案"的混淆页），**top3 命中率 8/8**，且多数查询 top1 即目标页。

**坑**：`MAX_SIM_COSINE` 的分数**不是余弦值**（可大于 1，只用于排序）；每页 patch 数不均衡时 MAX_SIM 天然偏爱块多的页——工程上要限制每页块数。

## 7.5A.5 Demo 5 · Search Aggregation：检索结果自带分面

**它解决什么**：电商/内容站的搜索页都有"类型/年代/地区"的facet卡片。老做法是把 top-K 全拉回应用里自己 groupby——K 大了传输和内存都疼。3.0 的 **`SearchAggregation`** 让 Milvus 在**服务端**边搜边分桶，一次请求返回：每个桶的 key、桶内命中总数、桶内 Top 命中。

**notebook**：`7.5A-05-SearchAggregation分面聚合.ipynb`。90 部合成电影（synopsis 嵌入），一次请求同时拿到：

- 按类型 6 个桶（Adventure/Comedy/... 各自 count 与 top3）；
- 加 `filter='primary_genre == "Comedy"'` 后按年代分面——**分面统计的是过滤后的分布**（Comedy 只有 5 个年代桶）。

**坑**：设置 `search_aggregation` 后 `limit` 参数被忽略（桶数由 `size=` 决定，pymilvus 会打 warning）；`bucket.key` 是**属性**且为列表（多字段聚合每元素一个字段），取值 `b.key[0]["value"]`；`count`（桶内命中总数）≠ `len(hits)`（只有 TopHits size 条）。
