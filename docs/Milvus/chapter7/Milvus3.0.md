# Chapter 7.0 Milvus 3.0：从 2.x 走过来

Milvus 3.0 正式版（v3.0.0）于 2026 年 7 月 29 日发布。本篇说明它和 2.x 的核心区别，以及本章各篇的安排；单个功能的细节都在后面各篇展开，完整的功能清单见官方发布说明（[https://milvus.io/docs/zh/release_notes.md](https://milvus.io/docs/zh/release_notes.md)）。

## 7.0.1 3.0 的新功能

**数据可以不搬进库里。** 这是 3.0 最大的变化：数据在湖上，检索就在湖上做，不再拷一份进库。外部 Collection 直接引用湖存储上的文件，原地建索引并检索，零拷贝、只读，并通过增量刷新实现同步。

**更多计算下推进服务端。** 过去只能把一大批结果取回客户端，自己在应用里排序、统计、重排；3.0 把这些搬进了内核：按价格、时间这类字段排序，在服务端直接完成；一次搜索同时带回「每个类目命中多少条」这类统计；Function Chain（函数链）把多个重排器串成一条链，在同一次请求里完成重排、排序和候选裁剪，无需客户端编排。

**Schema 可以在线改。** 加字段、补数据、删字段都直接在线上做，不用重建 Collection，也不用停服务。最典型的场景是换嵌入模型：给存量数据补算新向量，过去得新建集合把数据搬一遍，现在在原集合上加一列就能补——向量可以配个函数由后台慢慢算，也可以由外部任务算好写回。

**稀疏索引和写入引擎换代。** 稀疏向量检索有了新一代索引 SINDI：同样召回率下索引更小、查询更快，全文检索和混合检索直接受益。写入链路也换了新引擎 Woodpecker——可作为独立服务运行，通过增加副本水平扩展写入容量。

**升级要留意默认行为。** 新能力不随升级自动生效：Storage V3 默认关闭，需手动开启；新索引算法需手动提升目标索引版本才生效。3.0 部署可回滚至 2.6，但一旦启用会更改序列化数据格式的功能（如 Storage V3），回滚就不可再行。

## 7.0.2 本章各篇安排

本章按「基础 → 实战」主线组织，另配两篇深入篇（各篇内容均来自官方文档，出处见各节）：

- **7.1 环境升级（基础）**——从 2.6 升级到 3.0 的步骤，以及启用新功能要改的两个配置；
- **7.2 外部集合与快照（实战）**——湖上文件原地检索，快照隔离与回滚；含 MySQL 等常见数据源能不能接的核查；
- **7.3 数据模型与检索增强（实战）**——排序、聚合、分面、重排、多向量、TEXT、在线改列；
  - **〔深入〕FunctionChain 重排阶段（L0 / L1 / L2）**——三个阶段各自在哪执行、每层候选怎么流转、怎么选执行阶段与分数方向；
- **7.4 索引与性能选择（实战）**——3.0 的三类新索引：SINDI 稀疏（全文/稀疏 Embedding）、FAISS 直通（现成 Faiss 配方）、DiskANN 磁盘（晚期交互/超内存），外加一张「负载→索引」选型表；
  - **〔深入〕存储与写入引擎**——Vortex/Lance 存储格式、Woodpecker 写入引擎、强制合并、Storage V3 清单；7.2 那些反直觉行为的根子在这里；
- **7.5 端到端实战（实战）**——把 3.0 的升级点串成一条链路跑通。
